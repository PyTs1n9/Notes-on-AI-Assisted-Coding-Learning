# 华为杯模拟试卷01：学业预警 AI 系统构建

> 本卷依据 `../比赛相关/样题.md`、`../比赛相关/竞赛内容.md`、`../比赛相关/竞赛软件.md` 编制。样题确定了学业预警场景、分号分隔数据、成绩尺度及主要任务；本卷据此补齐六模块实操、配套数据、评分细则和交付契约。**本卷为训练用模拟卷，不冒充官方试题；360 分钟、分值分配、异常阈值和参数均为出题人自拟。**

## 【测试范围】

考核教育场景中的数据读取与探索、数据清洗、特征工程、分类建模、不平衡处理、交叉验证调优、风险画像和离线量化大模型报告。总分 **100 分**，建议用时 **360 分钟**，个人独立完成。允许查阅本地资料和库文档；正式模拟时不使用外部生成式 AI，不联网调用模型。提供的本地 GGUF 仅用于任务六。

本卷不以“已学过”为前提缩减比赛范围。逻辑回归是分类算法，与此前课程中的线性回归不同；LightGBM 为树模型。本卷属于比赛专项模拟，不改变原自主学习课程进度。建议先阅读 [数据说明](数据来源与字段说明.md) 和 [提交规范](提交目录说明.md)。

### 场景与预测边界

学校希望基于历史学生记录，识别期末不及格风险，帮助教师安排学业支持。原始资料来自葡萄牙中学，**不是中国职业院校真实数据**；本卷仅借用其字段模拟职校业务，不据此声称具有本校部署效果。

期末成绩 `G3` 低于 10 为高风险，标签 `warning` 为 1；其余为 0。`G3` 仅用于历史标签和评价。按样题“剔除平时成绩”的要求，本卷特征排除 `G1`、`G2`、`G3`、`warning` 和 `student_id`。预测时点假设为本卷行为信息已经采集、期末成绩尚未知；真实部署还须核实缺勤等字段的采集截止时间。

### 统一规则

- 只使用 `data/student_warning_exam.csv` 作答。原始备份仅供来源查证，不得以备份覆盖考试数据或绕过脏数据处理。考试文件用分号分隔，编码为 UTF-8 BOM；结果 CSV 用逗号分隔，`index=False`、`encoding=utf-8-sig`。
- 行级处理依次为：删除所有字段均缺失的空记录；按所有原始列去重，保留首次出现；删除 `G3` 缺失记录；保留原始顺序。不得把标签缺失者填成绩后用于训练，不把 `G3=0` 当缺失。
- 将完成上述处理并添加标签的记录称为“有效样本”。此阶段允许输入特征仍缺失。先固定训练/测试划分，再学习均值、众数、中位数、编码类别和标准化参数；测试集仅应用训练所得参数。交叉验证时这些步骤须在各训练折内重新学习。
- `absences` 大于 30 是本次模拟的**业务处理阈值**，不是原数据集公认的错误边界。缺勤均值和中位数均仅从当前训练部分中 0–30 的非缺失缺勤值计算；原有缺失缺勤用该均值填补，超阈值缺勤用该中位数替换，二者分别记录。其他数值输入缺失用训练均值，类别输入缺失用训练众数；众数并列时按字符串升序选首项。连续或等级数值填补后保留小数，不四舍五入。
- 样本划分、交叉验证和可设置随机种子的分类器均固定随机种子 42。测试集占 20%，按标签分层，划分前不额外打乱或排序。数值特征标准化，类别独热编码时保留全部类别并兼容未知类别；类别映射只在训练部分学习。
- 模型输出正类是 `warning=1`。分类阈值统一为 0.5，概率大于等于阈值判 1。指标保留至少四位小数；精确率或召回率分母为零时按 0 处理。ROC-AUC 使用正类概率。
- 每项任务都须保留实际执行代码、真实运行日志和文件产物。不得写死统计数、指标或概率，不要求学生逐行注释。没有真实模型推理时不得用固定模板伪装大模型输出。
- 无最低准确率、召回率或 AUC 过关线；按实现正确性、数据隔离、证据与分析评分。优化后测试指标可能下降，须据实解释。库版本导致的 dtype、对象显示和末位浮点差异不扣分。
- 环境准备不计入建议考试时间。沿用自己已有的运行习惯；若依赖未满足，先按 [开考前环境说明](开考前环境说明.md) 确认可运行路径，不因本卷自行更改现有环境。

## 【知识速览】

以下仅为工具索引，不给函数调用式；可采用功能等价方案，须符合统一规则。

| 名称 | 用途 | 易错点 |
|---|---|---|
| read_csv | 读取 CSV | 源文件为分号分隔 |
| dtypes、isna、describe | 查看类型、缺失与分布 | 原始统计与清洗后统计口径不同 |
| dropna、duplicated、drop_duplicates | 空记录与重复处理 | 别先填值再识别空记录 |
| SimpleImputer | 学习填补参数 | 只能在当前训练部分拟合 |
| train_test_split | 分层划分 | ID、特征、标签须保持对应 |
| OneHotEncoder | 类别编码 | 列对齐和未知类别 |
| StandardScaler | 数值标准化 | 不能在全量数据先拟合 |
| ColumnTransformer、Pipeline | 按列处理并串联 | 交叉验证须包含预处理学习步骤 |
| LogisticRegression | 逻辑回归分类 | 不得用线性回归替代 |
| LGBMClassifier | LightGBM 二分类 | 不得以别的树模型改名冒充 |
| predict_proba | 输出类别概率 | 核对正类所对应的列 |
| accuracy_score、precision_score、recall_score、f1_score、roc_auc_score | 评价分类 | 不只看准确率，概率与类别用途不同 |
| confusion_matrix | 统计错判类型 | 标明真实/预测轴及类别顺序 |
| StratifiedKFold、GridSearchCV | 分层交叉验证与网格搜索 | 调参不接触测试集 |
| joblib.dump、joblib.load | 保存和恢复流水线 | 不只保存分类器而丢失预处理 |
| Llama、create_chat_completion | 读取 GGUF 并生成中文 | 本地推理、提示词、原始响应均须留证 |

## 【测试题】

### 任务一：数据读取与探索性分析（12 分）

1. **T1.1，3 分**：读取考试数据，输出原始行列数、全部列名和数据类型；逐列统计缺失数量与缺失率，导出 `missing_profile.csv`，包含 `column,missing_count,missing_rate`。缺失率取 0–1 范围。
2. **T1.2，3 分**：统计全部字段均为空的记录数；在排除这些空记录后统计全行重复数。对**原始考试文件中非缺失的 `G3`**输出最小值、最大值、均值、中位数，不先删除重复记录。
3. **T1.3，4 分**：按成绩段 0–9、10–14、15–20 统计非缺失 `G3` 的频数，保存 `grade_distribution.csv` 和 `grade_distribution.png`；图的标题、轴名称和数值标注须与统计口径一致。
4. **T1.4，2 分**：在技术报告中说明数据最需要处理的问题，解释“原始统计”和“去重、删标签缺失后的统计”为何可能不同。

**验收点**：原始读入尺寸为 **658 行、34 列**；缺失表须覆盖全部原始字段，频数合计须等于所用口径的非缺失成绩数。图表和 CSV 可交叉核对，不以手工填入预期值代替计算。

### 任务二：数据清洗与预警标签构建（16 分）

1. **T2.1，4 分**：按统一规则完成空记录、重复记录和标签缺失处理；输出每步处理前后样本数，保存 `row_cleaning_log.csv`，包含 `step,before_rows,removed_rows,after_rows`。
2. **T2.2，4 分**：检查有效样本中的 `absences`，保存超阈值记录到 `absence_outliers.csv`，包含 `student_id,absences`。在报告写明后续填补与异常替换策略、统计参数的学习位置；具体拟合在任务三及各交叉验证折中执行。
3. **T2.3，4 分**：根据有效 `G3` 构建 `warning`，统计两个标签的数量和比例，保存 `label_distribution.csv`，包含 `warning,count,ratio`。保存 `eligible_students.csv`，保留原始列及标签；其中输入缺失与异常此时暂未填改。
4. **T2.4，4 分**：解释为什么不能用均值补 `G3` 后创建标签、为什么 `G3=0` 必须保留、为什么填补统计量不能从测试集学习。说明 `G1`、`G2` 的排除来自本卷预测时点及特征约定，而不是任何成绩任务都禁止使用历史成绩。

**验收点**：按规定顺序删除空记录 **4 条**、重复记录 **5 条**、标签缺失 **4 条**；`eligible_students.csv` 为 **645 行、35 列**，`student_id` 唯一，`G3` 和标签无缺失。高风险 **99 条**，低风险 **546 条**；有效样本中超阈值缺勤 **4 条**。该 CSV 仍存在输入缺失是本阶段的预期，不得误称全部特征已完成填补。

### 任务三：特征工程、分层划分与预处理（18 分）

1. **T3.1，3 分**：按统一规则排除禁用字段，保存特征/标签/ID 的对应关系，说明每个排除字段的理由。在不改变有效样本原始顺序的前提下完成训练/测试分层划分；导出 `split_ids.csv`，包含 `student_id,split,warning`，其中 `split` 只取 `train` 或 `test`。
2. **T3.2，4 分**：在当前训练部分学习填补与缺勤替换参数，对训练、测试分别应用；导出 `preprocess_parameters.json`，记录每个字段的训练统计量、众数选择结果、缺勤均值/中位数以及具体学习范围。填补后再构造衍生特征。
3. **T3.3，4 分**：构造至少两个有效衍生特征，至少包括 `low_study` 与 `has_failures`。`low_study` 表示学习时长编码不大于 2，`has_failures` 表示历史挂科次数大于 0，成立记 1，否则 0。额外特征须由允许输入构造、写明业务意义，不能使用标签或成绩。**studytime 是时长分档编码，不是精确小时数。**
4. **T3.4，4 分**：对数值输入及衍生数值做标准化，对类别输入独热编码；输出训练/测试编码前后尺寸及完整编码列名。导出 `train_features.csv` 与 `test_features.csv`，只包含最终编码后数值特征；列名一致、列顺序一致、无缺失和无无穷值。
5. **T3.5，3 分**：解释 `fit` 与 `transform` 在本题中的数据边界，以及为什么不能先在全量数据上独热编码和标准化后再评估。说明新增学生出现未知类别时的处理行为。

**验收点**：训练 **516 条**、测试 **129 条**；训练标签为低风险 **437 条**、高风险 **79 条**，测试为低风险 **109 条**、高风险 **20 条**。排除禁用列后、添加衍生特征前，输入为 **30 列**。编码后列数由实际特征方案决定，不要求抄写固定维度；须与保存的编码器、列名清单和模型输入一致。`student_id` 不进入模型，测试 ID 不参与任何统计量学习。

### 任务四：双模型训练、评估与保存（20 分）

1. **T4.1，5 分**：在相同训练/测试划分上建立两个基线模型：逻辑回归和 LightGBM 二分类器。逻辑回归正则化强度参数 `C` 取 1，`solver` 取 `liblinear`，最大迭代次数为 2000；LightGBM 树数 100、学习率 0.05、叶子数 15、CPU 线程数 1。两个基线的 `class_weight` 均不加权，随机种子均为 42，其余保持库默认。两者共享相同特征方案。
2. **T4.2，6 分**：对每个基线输出测试集准确率、正类精确率、正类召回率、F1、ROC-AUC，保存 `baseline_metrics.csv`。分别绘制混淆矩阵到 `confusion_lr.png`、`confusion_lgbm.png`，类别顺序为 0、1，轴需标明真实与预测。
3. **T4.3，5 分**：将两个模型的完整预处理与分类器分别保存为 `baseline_lr.joblib`、`baseline_lgbm.joblib`；允许以明确组织的多个对象构成同一个模型包。新进程加载后，对同一批原始测试输入重新输出概率，计算保存前后概率最大绝对差并写入日志。不得只打印“已一致”。
4. **T4.4，4 分**：从“尽量不漏掉高风险学生”的角度解释两模型差异，结合自己的混淆矩阵指出漏判数与误报数。说明测试集比较属于效果分析，不能据此不断调参或直接声称已选出可上线最优模型。

**验收点**：评价对象都是同一测试集，两个混淆矩阵元素总数均等于测试记录数；所有指标能从保存概率和标签复算。模型重载前后概率最大绝对差不大于 **0.0000000001**。若采用自定义转换器，必须提交其定义文件并验证新进程可加载，不接受仅在当前会话中偶然恢复成功。

### 任务五：不平衡优化、网格调优与风险画像（18 分）

1. **T5.1，3 分**：解释标签不平衡及只追求准确率的风险。除原基线外，建立带 `balanced` 类别权重的逻辑回归，使用相同折划分评价训练数据；本卷不要求额外安装过采样库。
2. **T5.2，6 分**：对逻辑回归执行网格搜索：`C` 候选为 0.1、1、10，类别权重候选为不加权与 `balanced`。采用打乱的 5 折分层交叉验证，随机种子 42，优化指标为高风险召回率。所有填补、缺勤替换、编码、标准化及衍生特征步骤纳入折内流程。按题面候选顺序构造搜索；均值并列时保留候选顺序中最先者，不使用测试成绩打破并列。保存 `cv_results.csv`，含候选参数、每折验证召回率、均值、标准差和排名。报告最佳参数和训练交叉验证成绩。
3. **T5.3，3 分**：最佳参数在全部训练样本上重新拟合后，评估一次测试集，保存 `optimized_metrics.csv`；与两个基线比较并解释召回、误报和准确率的取舍，不能把“尝试优化”直接写成“所有指标提升”。本卷固定以优化后的逻辑回归作后续风险输出，基础 LightGBM 用作对照。
4. **T5.4，3 分**：导出 `feature_importance.csv`，至少分别给出优化逻辑回归的系数及绝对值、基线 LightGBM 的重要性；包含 `model,feature,importance,signed_value`，LightGBM 的 `signed_value` 可留空。绘制两个模型各自前十的重要性图，并解释逻辑回归正负方向。全局重要性只代表模型关联，不能作为因果证据或冒充每个学生的局部贡献。
5. **T5.5，3 分**：保存全部测试记录到 `test_predictions.csv`，包含 `student_id,y_true,baseline_lr_probability,baseline_lgbm_probability,optimized_probability,y_pred`。按优化概率降序、ID 升序打破并列，输出前五名到 `risk_top5.csv`，包含 ID、概率、阈值判定、填补/修正后的 `studytime,failures,absences,low_study,has_failures`。把它称为“优先复核名单”；若概率未过阈值，不得仍称已经判为高风险。保存优化完整流程为 `optimized_lr.joblib`。

**验收点**：网格覆盖 **6 组**候选，每组 **5 折**；训练折和验证折不得共享已拟合预处理器。全部测试概率在 0–1 范围，ID 与划分表匹配；名单顺序可以由预测表重建。重要性记录必须能与实际编码列对齐。优化流程保存后同样执行新进程概率一致性检验。

### 任务六：离线量化大模型个性化预警报告（16 分）

使用提供的 `qwen2-0_5b-instruct-q4_k_m.gguf`，实际加载路径为模拟卷上一级目录中的 `比赛相关/轻量量化模型/`。不得下载或替换模型，不使用在线 API 代替。允许通过既有 `llama-cpp-python` 或既有 `llama.cpp` 可执行程序完成本地推理；提交路径、版本、参数和原始输出即可，不限制必须在同一 Python 进程中完成全部任务。

1. **T6.1，4 分**：读取 `risk_top5.csv`，先为最高优先级记录设计一份结构化提示词，再实际加载并调用 GGUF。基础推理设为 CPU，`n_gpu_layers` 为 0、上下文长度 2048、随机种子 42、温度 0、最多生成 384 个 token；CPU 线程数可按硬件选择并记录。出现截断可将生成上限提高到 512 并说明；只要总上下文足够，其他运行参数调整须有日志。系统提示和用户输入必须分别保存。
2. **T6.2，4 分**：为名单中每位学生生成一份中文报告，按 `reports/学生ID.md` 保存，包含“风险情况、已知依据、支持建议、人工复核提示”四部分。输入只含匿名 ID、模型概率与判定、上述学业行为字段、必要的字段释义和输出约束；不向模型传入 `G3`、真实标签、姓名、家庭职业、健康或饮酒信息。报告所称概率必须与分类器输出一致；需说明概率是模型估计，非事实断言。
