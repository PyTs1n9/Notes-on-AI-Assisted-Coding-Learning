## 4. 错误点参考答案

### 4.1 类型转换先后

不能先用 `uint8` 相减再转浮点。原像素首个 RGB 为 `[3, 22, 60]`，偏移为 `[8, 30, 70]`，正确结果含负值。若先在 `uint8` 中计算，负数已经发生无符号整数回绕；之后转为 `float32` 只能转换回绕后的数字，不能恢复原本的负值。因此两个减法操作数都应先转为能够表示负数的类型，再执行减法。

### 4.2 CHW 下的广播方向

HWC 中最后一根轴是通道，所以长度为 3 的偏移可以自然对应 RGB 通道。换成 CHW 后，三根轴依次是通道、行、列；一维张量默认从最右侧轴对齐，长度为 3 的偏移会对齐到宽度轴，而不是通道轴。正确做法是把偏移显式调整为 `(3, 1, 1)`，再与 CHW 相减。

本题中错误广播仍能运行，shape 也仍为 `(3, 2, 3)`，但 `torch.equal` 为 `False`。这证明“代码能运行”和“shape 相同”都不足以证明颜色语义正确。

### 4.3 设备默认值和返回值

设备选择要先设 CPU 默认值，再检查 CUDA：

```python
# 老师参考：CPU是所有环境都可用的默认设备。
device = torch.device('cpu')
if torch.cuda.is_available():
    device = torch.device('cuda:0')

# 老师参考：.to()返回转换后的张量，必须接住。
on_device = pixels_b_chw.to(device=device)
back_on_cpu = on_device.to(device='cpu')
```

如果把 `device` 只写在 `if` 内部，CUDA 不可用时后续代码会引用不存在的变量。搬回 CPU 后再用完整张量比较，才能确认设备迁移没有改变数值。
